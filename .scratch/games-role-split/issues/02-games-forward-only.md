# 02 — `games` 收斂成純前瞻表：只抓現役球隊、窗口往未來拉、過期即清

**What to build:** 票 01 拆掉 FK 之後，`games` 的唯一消費者剩下 `player-upcoming.ts:75-101`（下一系列賽、先發預告、球隊近期戰績），也就是它本來該是的那張「即將的比賽」表。本票把 ingest 與保留策略收斂到這個角色。

**現況三個問題**（2026-08-03 重新實測，**2877 筆**；括號內為 07-29 開票時的數字）：

| 問題 | 數字 |
|---|---|
| schedule 每批對六個 sportId **掃全聯盟**，不按球隊過濾 | **1133 筆（39%）**跟任何 tracked 球員都無關，且無人參照、只增不減（07-29：929 筆／35%）。**單一批次就增加 204 筆**，成長速率比開票時估的更快 |
| 窗口是 `today-1 .. today`（`games.py:222` 的 `_schedule_window`）——**從不抓未來** | 全表 **只有 2 筆**日期 `>= 今天`，而 `scheduled` 有 139 筆（幾乎全是過期的）；`player-upcoming.ts:85` 要求 `>= today` → **「下一系列賽」實際上全空**（07-29：41 筆 scheduled 全為 07-27） |
| 沒有保留策略 | 過期的 `scheduled` 與全聯盟殘留永久留著 |

### 「球隊近期戰績」—— 決策已定：保留窗口往前留 7 天（2026-08-03，batu）

`player-upcoming.ts:92-101` 查球員所屬**球隊**最近 3 場 `status='final'`，`components/player-detail/upcoming.tsx:58-75` 顯示日期／勝敗／比分，**僅個人頁**（首頁的 upcoming 區塊以 `skipRecentResults` 跳過這個查詢）。原本會被保留策略清掉，決策為**保留、窗口往前留 7 天**。

**原先列的選項 (b)「改由逐場表推導」經查證做不到**，記在這裡免得日後有人再提：

1. **逐場表只有 tracked 球員自己出賽的場次**。「球隊最近 3 場」包含該球員沒上場的比賽（尤其是替補／輪值投手），逐場表裡根本沒有那些列
2. **逐場表沒有比分欄**。票 01 明確只帶 `game_date_us`／`opponent_team_id`／`is_home` 三欄，並在 Comments 接受了「日後要顯示比分得另外帶欄位」這個代價。勝敗與比分都推不出來

所以要嘛保留 `games` 的過去窗口（採用），要嘛拿掉該區塊。

- 元件已經是 `recentResults.length > 0 &&` 才渲染，所以窗口內湊不滿 3 場時會自然少顯示幾列或整段不顯示，**不需要額外的空狀態處理**。
