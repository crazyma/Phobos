產品需求文件（PRD）— 台灣球員大聯盟網站

從產品／服務面描述這個服務要解決什麼、為誰做、提供哪些具體功能。技術「用什麼、為什麼」見 adr/decisions.md；欄位級規格見 spec/（2026-07-23 重建版，入口 spec/spec-00-overview.md；舊版封存於 archive/spec/）。本文件是那兩者的上游。

類型 產品需求對象 台灣棒球迷版本 v1 範疇語言 繁體中文

產品定位

一個繁體中文的網站，讓台灣棒球迷能在同一個地方追蹤台灣球員在美國職棒（大聯盟與 3A／2A 小聯盟）的表現與動態，並附帶介紹現代棒球的規則與數據名詞。

  • 一句話：台灣球員在美職的中文戰情室 + 棒球知識入口。
  • 背景：初期為開發者的個人／學習專案，但產品目標對真實使用者（台灣球迷）有價值，設計以使用者需求為準，而非只當練習。

目標使用者

使用者類型特徵主要需求
關注型球迷（主要）平常追某幾位台灣球員，想知道「他最近如何、上大聯盟了沒、有沒有受傷」快速看到球員近況、動態、數據，中文、不用翻英文網站
數據型球迷想看較完整的打擊／投球數據、跨球季比較結構化、正確、可比較的數據呈現
入門球迷 / 路人看比賽或新聞時遇到不懂的名詞（wRC+、FIP、IL…）用中文快速查到名詞／規則的白話解釋

客群定位已定（見 §9.1）：兩者兼顧、關注型優先。名詞解釋所服務的「看到名詞→進站查」情境，是刻意重視的核心情境之一。

使用者面臨的問題（為什麼需要這服務）

  1. 台灣球員散布在不同球隊、不同層級（大聯盟／3A／2A），資訊分散在多個英文網站，沒有一個中文的集中處。
  2. 官方英文數據網站對一般球迷門檻高（語言、名詞、資訊過載）。
  3. 球員的「動態」（升上大聯盟、被下放、交易、進傷兵名單）常常臨場才公布、且不易一眼看到時間軸。
  4. 遇到現代棒球名詞（進階數據、規則）時，缺乏中文、簡潔可信的解釋。

產品範疇

4.1 這一版要做（v1）

  • 功能一：台灣球員追蹤（動態內容）
  • 功能二：棒球規則／名詞介紹（靜態內容）

4.2 設計上預留、這版不做

  • 功能三：新聞（爬取官網／社群新聞並呈現）
  • 功能四：專欄（寫手發布針對台灣球員的文章、規則更新消息）

4.3 明確不在範疇（v1）

  • 逐球（pitch-level）等級的細部數據與圖表
  • 使用者帳號、留言、社群互動
  • 即時比分推播 / 通知訂閱（可能列入 future）
  • 付費 / 會員機制

功能需求（具體描述）

F1. 台灣球員追蹤

追蹤名單為人工維護的台灣球員白名單（歷史上台籍美職球員僅十幾位，可控）。成績涵蓋所有能抓到資料的層級——從大聯盟、3A、2A，一路到 1A、新人聯盟；只要來源有資料就呈現（多數台灣球員剛進體系、主要在低階層級，若只做高階幾乎沒東西可看）。升降／異動涵蓋所有層級。

#### F1-0 首頁（動態導向）

首頁以「最近發生 + 即將發生」為主軸，不放全員名冊：

  1. 最近 24 小時（主）：這段時間內的比賽結果與球員動態（升降 / 交易 / 傷兵進出等），彙整成動態流／摘要。每則賽果可帶該球員的近況一句話（見 §7.4）。
  2. 即將發生（次）：球員的下一場出賽預告（是否先發、台灣時間，見 F1-2 第 5 區的定義）。
  • 球員名冊不佔首頁主體，改放在 top bar / side bar 的導覽入口；名詞介紹（F2）同樣從全域導覽進入。
  • 動態中的單場數據沿用 §7.2「今日快訊＝單場精簡」。
  • 「24 小時」為顯示概念，實際資料隨一天兩次同步更新（見 F1-3）。
  • 空狀態 / 休賽期：淡季或當日無台灣球員出賽時，首頁改顯示本季／上季回顧卡 + 名詞知識入口輪播（見 §9.1 2026-07-23），不留白。

使用者故事：作為關注型球迷，我一打開網站就想看到「這一天發生了什麼、我關注的球員接下來何時出賽」，不用自己一個個點。

#### F1-1 球員總覽頁

  • 從全域導覽（top bar / side bar）進入；列出所有被追蹤的台灣球員。
  • 每位球員以卡片／列呈現一眼可懂的近況：目前所屬球隊、所在層級（大聯盟／各級小聯盟）、目前名單狀態（出賽中／傷兵／小聯盟）、以及一項近期表現摘要。
  • 可依「目前層級」「球隊」等排序或篩選（細節待定）。

使用者故事：作為關注型球迷，我想在一頁看到所有台灣球員現在人在哪一隊、哪一層、狀態如何，不用一個個查。

#### F1-2 球員個人頁

單一球員的完整戰情，重點元素：

  1. 基本資料 + 近況一句話：中英文名、守備位置、打擊／投球慣用手、生日、目前所屬球隊與層級、目前名單狀態；並在顯眼處放一句話近況（≤20 字、自動生成，見 §7.4），一眼抓到手感。
  2. 球季數據：依球季、依層級（大聯盟到小聯盟各級）呈現標準季賽數據 + 一組進階數據（明細見 §7.3）；資料從 2020 球季起（未來可往前補）。低階層級資料可能稀疏，抓得到就顯示。
  3. 逐場成績（近況細節）：最近 N 場的逐場 box line（打者：打數／安打／全壘打／打點／保送／三振…；投手：局數／被安打／失分／自責／三振／保送…），給想細看手感的人。
  4. 動態時間軸：升上大聯盟 / 下放小聯盟 / 交易 / 進出傷兵名單 / 被 DFA、釋出等異動，依時間排序成時間軸。
  5. 出賽預告 + 下一個系列賽：
    • 出賽預告：下一場是否出賽——「確定先發」僅適用投手（probable pitcher，通常賽前數日可知，需明顯標示）；野手與中繼／後援一律標「可能出賽」——先發打線賽前 3~4 小時才公布，一天兩批的同步節奏（F1-3）無法及時取得，故不承諾打線。開賽時間以台灣時間呈現。
    • 下一個系列賽：至少呈現下一個系列賽的對手與地點（例：本系列在舊金山、下一系列到紐約），並附最近幾場結果。
    • 轉播／觀看服務資訊：日後以爬蟲補，優先度較後。

使用者故事：作為球迷，我想在球員頁一眼看到他最近手感（近況一句話）、這季打得如何、最近有沒有被升降或受傷、下一場台灣時間幾點、會不會先發。

#### F1-3 資料新鮮度

  • 每頁需標示資料最後更新時間，讓使用者判斷新鮮度。
  • 更新頻率為一天兩次（早上結算前一天賽果與累計數據；傍晚同步當日賽程、異動與傷兵名單）。

#### F1-4 收藏「我的球員」（低優先 / 加分項）

  • 讓使用者釘選常追的球員（localStorage，無需帳號），名冊／首頁優先顯示。
  • 低優先：球員與每日賽事量都不大（一天有台灣球員的比賽常不到 10 場），一次瀏覽即可看完，故列為有餘力再做。

F2. 棒球規則／名詞介紹

使用者通常是在站內或站外看到某個名詞、想搞懂它才點進來——目標是幫他讀懂當下的脈絡，而非教科書式從定義講起。

#### F2-1 涵蓋範圍（逐步累積）

  • v1 優先：數據名詞——先把球員頁會用到的進階數據（打投各 7 項）與常見標準數據講清楚（wRC+、FIP、OPS、WHIP、IL、DFA、waiver…），起手約 20~30 則高頻名詞（這組進階數據為必做核心）。
  • 第二批：基本規則（好球帶、盜壘、犧牲打…）。
  • 更後面：戰術／玩法、規則更新消息。
  • 靜態內容、逐步新增；撰寫採 AI 輔助草擬 + 人工校訂。

#### F2-2 單頁內容結構（解讀優先）

每則名詞頁由上而下三層，重點在「怎麼幫使用者判讀」：

  1. 主要（最上、最顯眼）——「這在看什麼、怎麼判讀」
    • 一句白話點出它衡量什麼。
    • 數值大概的分布範圍。
    • 級距對照：哪個區間算及格／不錯／厲害／MVP 等級。← 這頁的主角。
  2. 次要（下方、字級較小）——名稱與算法：中英文名、定義、計算方式；點到為止，不必像 wiki 那麼細。
  3. 延伸（最後）——原始權威來源：附 MLB／Baseball Savant 等原始介紹頁連結，讓想深鑽的人自己去讀。

範例（OPS）：先講「衡量打者整體進攻能力，聯盟大致落在 .600~1.000，.800 算不錯、.900 以上明星級、破 1.000 是 MVP 等級」；下方小字補「OPS = 上壘率 + 長打率」；最後給 MLB 官方說明連結。

#### F2-3 與球員數據雙向連結

  • 球員頁上的數據（如 wRC+）可點進對應名詞頁；名詞頁亦可回連範例球員，形成 F1×F2 整合。

#### 其他

  • 以主題分類組織，內容可瀏覽、（理想上）可搜尋。

使用者故事：作為入門球迷，我在文章看到「OPS .950」不懂算好算壞，點進名詞頁一眼就知道「這是明星等級」，不用先看公式。

非功能需求

面向需求
語言介面與內容以繁體中文為主；球員英文原名保留以利對照。
SEO公開內容（球員頁、名詞頁）需能被搜尋引擎索引；使用者常從 Google 搜球員名／名詞進來。
社群分享球員頁／亮點需可分享到 LINE、Threads、社群——分享連結帶 Open Graph 預覽（標題、球員近況、logo），兼作自然流量入口。
裝置響應式設計，手機優先（球迷多在手機上看）。
效能頁面載入要快；靜態知識內容尤其應接近即時。
正確性數據來自可信來源；上游若事後修正，網站數據需跟著更新（不是抓一次就固定）。
可用性／韌性即使背後資料同步暫時失敗，網站仍能顯示既有內容，不因資料層問題而整站不可用。

內容 / 資料呈現需求（產品視角）

7.1 動態與狀態

  • 球員動態類型（要能呈現）：升上大聯盟、下放小聯盟、交易、被指定轉讓（DFA）、釋出、進／出傷兵名單。
  • 名單狀態（要能呈現）：出賽中（active）、傷兵名單（IL）、小聯盟（minors）等，並保留歷史以畫出時間軸。
  • 層級標示：清楚標明每筆成績屬於哪一層級（大聯盟／3A／2A／1A／新人聯盟…），避免混淆。

7.2 數據呈現深度依「情境」而不同

數據深度不是單一答案，依出現的頁面/情境決定：

情境深度內容
今日快訊（單場，如首頁快訊卡）精簡、單場打者：打席、安打、全壘打、打點、保送、三振。投手：局數、被安打、失分、自責分、三振、保送。「一眼看完今天幹了啥」。
球員頁標準季賽數據 + 一組進階數據見 §7.3。

7.3 球員頁的數據分層

  • 標準季賽數據：一般球迷看得懂的常見數據。
    • 打者：AVG / OBP / SLG / OPS、HR、RBI、SB、BB、SO…
    • 投手：ERA、WHIP、IP、K、BB、W-L、SV、HLD…（WHIP 為未校正的簡單比率，歸此層而非進階）
  • 進階數據（可調整清單，不寫死）：先挑一組打者、一組投手當起點（目前各 7 項），之後持續增減／替換（呼應棒球演進）。

打者進階（7 項）

指標說什麼故事
wRC+校正球場/聯盟後的綜合打擊，100=聯盟平均（頭號指標）
wOBA加權上壘率，整體攻擊產出
ISO純長打率（SLG−AVG），power
BB%保送率（選球眼）
K%三振率（接觸/選球風險）
WAR打擊+跑壘+守備的單一總值
BABIP場內球變安打的比率，反映接觸品質與運氣（偏離常態代表可能回歸）

投手進階（7 項）

指標說什麼故事
FIP獨立防禦率，排除守備/運氣，比 ERA 更貼近真實
K%三振率（宰制力）
BB%保送率（控球）
HR/9每 9 局被轟（長打壓制）
LOB%殘壘率（危機處理/運氣，判斷 ERA 是否回歸）
WAR投手綜合價值單一數字
BABIP被打進場內的球變安打的比率，判斷運氣成分（過低可能好運、將回歸；與 LOB% 相輔）
  • 口袋替補（日後想換時）：打者 OBP；投手 xFIP（StatsAPI sabermetrics 可得，2026-07-23 實測確認）、~~SIERA~~（仍無來源）、K-BB%（自算）、xERA（Savant）、WHIP。
  • 可用性：進階數據多在 MLB / 高階小聯盟才齊全（wRC+/WAR/FIP 需聯盟/球場係數）；低階層級算不出來就不顯示（best-effort）。多數台灣球員在低階、進階數據常空白——因此進階數據視為重要但非 v1 首要，完整化可延續到下一 phase。
  • 來源應變（2026-07-23，詳 §9.1）：wRC+／WAR 的原定來源（FanGraphs）不可得（adr §6.4）→ 同日實測 StatsAPI stats=sabermetrics 命中（wOBA/wRC+/WAR/FIP/xFIP；僅 MLB 層級，小聯盟缺值本就 best-effort 不顯示；2020~ 可回查）——維持現清單，遞補鏈（wRC+→xwOBA→wOBA）與 WAR 移除等預案封存不啟動。

7.4 近況一句話（自動生成的自然語言）

  • 用一句話（≤20 字）描述球員近況，讓輕量使用者「一句看懂手感」，勝過只丟一排逐場 log。
  • 例：「連續 5 場有安打」「上一場 3 支安打」「上一場投出生涯最多 8 次三振」「近 3 場防禦率 1.20」。
  • 由近期逐場成績自動歸納產生（連續紀錄、單場亮點、個人／生涯新高等 pattern）。
  • 出現位置：球員頁顯眼處與首頁今日快訊（F1-0、F1-2 共用）。

成功樣貌（v1 做到什麼算成功）

  • 名單內每一位台灣球員，都能在站上看到：他現在在哪隊哪層、目前狀態、本季主要數據、最近的升降／傷兵動態。
  • 使用者能在一頁看懂某位球員的近況，不需再去英文網站。
  • 常見棒球名詞能用中文查到解釋。
  • 球員頁與名詞頁能被 Google 搜到。

產品決策

產品面決策，與 spec/ 的技術未決項不同。

9.1 已定

  • ✅ 主要客群：兩者兼顧、關注型優先——預設呈現簡潔近況與動態，進階數據可展開或放次要位置。
  • ✅ 首頁形態：動態導向——主軸為最近 24 小時（比賽結果 + 球員動態），其次為即將發生（下一場比賽）；球員名冊改放全域導覽（top / side bar）入口，不佔首頁主體（見 §5 F1-0）。
