## 1. 核心實體與主鍵

| 實體 | 主鍵（識別） | 說明 |
|---|---|---|
| `Player` 球員 | 上游球員 ID | 人工白名單；生命週期：**追蹤中 / 已離開**（離開美職體系者轉精簡存檔頁） |
| `Organization` 球團 / `Team` 所屬球隊 | 上游隊伍 ID | 母球團與各級 affiliate 是兩個概念，PRD 混稱「球隊」，模型需分開 |
| `Level` 層級 | 列舉 | MLB / 3A / 2A / 1A / 新人聯盟… |
| `TransactionEvent` 動態事件 | 球員 × 事件時間 × 事件類型 | 升 / 降 / 交易 / DFA / 釋出 / IL 進出；**真相來源（event-sourced）** |
| 目前狀態（歸屬 × 健康） | 球員（唯一） | **由事件流推導的投影**，非獨立同步；詳 §2 |
| `GameLine` 逐場成績 | **球員 × 比賽 × 角色（打者/投手）** | 野手投球、二刀流同場兩列；角色由當場行為決定，非守位 |
| `SeasonStats` 球季數據 | **球季 × 層級 × 球隊**（＋衍生層級合計列） | 比照官方慣例：分隊列出＋該層級 total；合計可由明細推導 |
| `UpcomingGame` 出賽預告 | 球員 × 比賽 | 投手＝確定先發（probable）；野手／牛棚＝一律「可能出賽」 |
| `Series` 系列賽 | 對戰組合 × 起始日 | 對手、地點＋最近幾場結果 |
| `RecentForm` 近況一句話 | 球員（每批重算） | 衍生資料；優先序＋狀態 fallback，詳 §5 |
| `GlossaryTerm` 名詞 | slug | 三層結構；級距分層級（MLB/3A/2A），詳 §6 |
| `SyncRun` 同步批次 | 批次時間 | 「資料最後更新時間」的來源；一天兩批 |

## 2. 狀態模型：歸屬 × 健康（兩軸）

PRD 原文「active / IL / minors」混了兩個維度，拆為：

- **歸屬軸**：在哪一級哪一隊——MLB／3A／2A／…／DFA 中／FA／已釋出／已離開美職體系。
- **健康軸**：active／IL（**各層級都可能進 IL**，小聯盟 IL 也要能表達）。

呈現時組合成一句（例：「3A・傷兵名單」「大聯盟・出賽中」「DFA 等待處置」）。

**投影規則**：目前狀態一律由 `TransactionEvent` 事件流推導，時間軸與目前狀態**天然一致、不可能矛盾**。上游漏事件時，以**人工補錄事件**修正，禁止直接改狀態快照。

## 3. 成績模型

- `SeasonStats` 最細粒度＝球季 × 層級 × 球隊；同季同層級跨隊（交易）分列，另出層級合計。**不做跨層級加總**（不同層級數據不可比）。
- `GameLine` 帶角色軸：打者欄位組／投手欄位組各一型；同球員同場可兩列。
- 資料自 **2020 球季**起；「生涯新高」pattern 照樣稱生涯，接受基準誤差（多數現役球員 2020 後登美職）。
- 進階數據 best-effort：低階算不出（缺聯盟/球場係數）就不顯示。

## 4. 首頁「24 小時」窗口

錨定「**最新一個已結算的美國比賽日**」全部賽果＋其後發生的動態事件，**不是**滾動 24 小時時鐘窗口——避免同一比賽日的內容在台灣時間下午陸續「過期消失」，語意也跟一天兩批的同步節奏相容。

## 5. 近況一句話（RecentForm）生成規則

1. **Pattern 優先序**：生涯／球季新高 → 連續紀錄 → 單場亮點 → 近 N 場數據。多 pattern 同時成立取最高優先。
2. **狀態 fallback**：無近期賽事資料時退化為狀態句——「傷兵名單中，最後出賽 6/12」「休賽期」「新人聯盟（無逐場資料）」。此欄**永不為空**。
3. 每批同步重算（回填修正自動反映）。

## 6. 名詞庫（GlossaryTerm）模型

- **級距 × 層級**：級距對照做 **MLB／3A／2A 三組**；1A 以下不給級距，數據旁附「低階層級數據僅供參考」警語。低階聯盟無權威參考區間，不硬做。
- **指標 ↔ 名詞頁對應**：球員頁**僅能顯示已有對應名詞頁的指標**——換進階指標時名詞頁先行，舊名詞頁保留不下架。此規則保證雙向連結永不斷鏈。
- **範例球員回連**：自動挑選（追蹤中＋該指標有值＋樣本足夠，依層級優先）；挑不到則整塊隱藏，不硬塞。

## 7. 出賽預告語意

- 「**確定先發**」僅適用投手（probable pitcher，賽前數日可知）。
- 野手／中繼／後援一律「**可能出賽**」＝球隊有比賽且球員健康在名單——**不承諾打線**（打線賽前 3~4 小時才公布，一天兩批同步必然錯過；不為此加開第三批）。

## 8. 上游修正回填（正確性條文的落地邊界）

| 資料 | 回填範圍 |
|---|---|
| 季累計 | 每批**整季重拉**（追蹤球員僅十餘人，成本可行） |
| 逐場 | 每批回看**近 7~14 天** |
| 近況一句話 | 每批全量重算 |
| 更早的逐場修正 | 手動觸發 |

## 9. 通用語言（Ubiquitous Language）

| 詞 | 定義（本專案語意） |
|---|---|
| 動態（transaction） | 升 / 降 / 交易 / DFA / 釋出 / IL 進出等異動**事件** |
| 狀態 | 歸屬 × 健康的**目前投影**，由事件推導 |
| 比賽日 | **美國比賽日**（首頁窗口的錨定單位） |
| 確定先發 | 僅投手；probable pitcher |
| 可能出賽 | 球隊有賽＋球員健康在名單，不承諾上場 |
| 近況一句話 | ≤20 字、每批重算、永不為空的衍生欄位 |
| 級距 | 名詞頁「及格／不錯／厲害」對照，分 MLB/3A/2A 三組 |
| 存檔頁 | 已離開美職體系球員的精簡頁（基本資料＋生涯總成績） |
