# UI 拉皮研究 — 以 Phobos-UI 雜誌風設計改寫前端（2026-08-12）

> 研究外部設計專案 `Phobos-UI`（v0 產出、雜誌跨頁風格，自帶設計指南頁）能否用來改寫本站前端。結論：**技術棧同源、可直接搬**，但設計覆蓋的資訊深度只有現行的一部分，且與 PRD 的「不放球員照片」決策正面衝突。

> 本文只做研究與對照，**不含實作切片**。四個待決項（§5）拍板後再開票到 `.scratch/ui-reskin/issues/`。

## 0. 一句話結論

搬的是 **design token 與版面樣板**，不是元件庫——設計專案通篇手刻 Tailwind，`@/components/ui/*` 的 import 數是 **0**。因此拉皮的成本不在依賴，在於**補齊設計沒畫到的那些頁面區塊**，以及**先解決球員照片這個產品決策衝突**。

### 1.1 設計專案沒有用元件庫

全域 grep `@/components/ui/` 在設計專案的 `app/`＋`components/` 命中 **0 筆**。`components/ui/button.tsx` 存在但無人引用，且與我們的 `components/ui/button.tsx` 幾乎逐字相同（差異只有引號風格與兩處 hover class）。

**⇒ 拉皮不需要新增任何 npm 依賴。**

### 1.2 需要動的三件事

1. **字體（唯一的新東西，但走 `next/font/google`，免安裝）**
   現行 `app/layout.tsx:11` 只有 `Geist`。設計要三種角色分工，這是雜誌風格的骨幹：
   - `Noto_Serif_TC` → `font-serif`：所有標題、人名、區塊大標
   - `Noto_Sans_TC` → `font-sans`：內文
   - `Geist_Mono` → `font-mono`：**所有數據與標籤**（設計原則之一：數據一律等寬以維持對齊）

2. **`app/globals.css` 的語意 token**
   設計新增 8 個我們沒有的變數，並在 `@theme inline` 註冊：
   `--mlb / --aaa / --aa`（層級色）、`--up / --down`（升降・好壞）、各自的 `-foreground`。
   色盤本身：深藍 `--primary: oklch(0.32 0.09 262)`、暖橘 `--accent: oklch(0.68 0.17 45)`、頁面底 `oklch(0.98 0.006 250)`。

   - ⚠️ **層級數對不上**：設計只定義 MLB/3A/2A 三階，我們的 `LEVEL_ORDER`（`components/players/players-view.tsx:11`）有 **六階**（`mlb / aaa / aa / a_plus / a / rookie`）。需自行補 `--a-plus / --a / --rookie`（建議自 `--aa` 的灰再降階），否則低階球員 badge 無色。
   - ⚠️ **設計沒有深色模式**：`:root { color-scheme: light }`、無 `.dark` 區塊（雖仍宣告 `@custom-variant dark`）。我們現行 `globals.css:85-117` 有完整深色盤。→ 待決 §5.2。

3. **補設計沒有的元件**：見 §3。

## 2. 頁面對應

| 設計頁 | 我們的頁 | 對應狀況 |
|---|---|---|
| `/magazine` | `/` | ⚠️ 骨架不同（缺即將出賽、缺 empty state） |
| `/magazine/roster` | `/players` | ⚠️ 缺篩選／排序／archived |
| `/magazine/players/[id]` | `/players/[id]` | ⚠️ 資訊深度差最多 |
| `/magazine/glossary` | `/glossary` | ⚠️ **設計是 modal，我們是獨立頁** |
| — | `/glossary/[slug]` | ❌ 設計完全沒有 |
| `/magazine/questions`（我想知道） | — | ➕ 全新頁 |
| `/magazine/styleguide` | — | ➕ 設計指南本身 |

### 2.1 首頁

- **設計**：大標 → 封面人物跨頁（大圖＋人物簡介＋四格數據）→ 近期賽果 → 異動快訊。
- **我們**（`components/home/home-page.tsx`）：最新賽況 → 球員動態 → **即將出賽** → 外加整套 `emptyState`（休賽季的本季／上季回顧＋名詞推薦）。

**設計缺**：即將出賽整區、`emptyState` 整套。前者是 PRD §9.1 已定的功能。
**設計多**：封面人物需要 `headshot` + `summary`（人物介紹段），DB 兩個欄位都沒有。

### 2.2 球員名冊

- **設計**：依 MLB/3A/2A 分區，每區標題列＋人數；卡片有編號浮水印、頭像、三格數據。
- **我們**：層級下拉 + 排序下拉 + archived 折疊區；卡片有「狀態一句話」與「近況一句話」。

**設計缺**：篩選／排序 UI、archived 區、狀態一句話的位置。
**設計多**：頭像、編號浮水印。

### 2.3 球員個人頁（差距最大）

設計 7 區：返回列 → hero → 檔案資訊（摘要＋4 格 dl）→ 近期比賽紀錄（`StatList`）→ 近況走勢 sparkline → 媒體與新聞集錦 → 本季數據（`StatCards`）→ 逐季歷史表 → 個人動態。

我們 5 區（spec-02 §2.3）：hero → 球季數據 → 逐場成績 → 動態時間軸 → 出賽預告。

**設計缺**：

- **出賽預告整區**（下一系列賽、確定先發／可能出賽／傷兵中、台灣時間、近期戰績）——無任何對應樣板。
- **進階數據展開區**（`components/player-detail/season-stats.tsx:132` 的 `<details>`，每項連回名詞頁）。
- **完整數據表的資訊量**：我們打擊 20 欄、投球 20 欄（`season-stats.tsx:24-68`），另有 per-team 分列＋**合計列**＋「低階層級數據僅供參考」註記。設計的 `StatCards` 一個層級只放 **4 個**大數字——這不是樣式差異，是差一個量級，需要「4 格重點 + 可展開完整表」的折衷。
- **archived 球員**的「已離開美職體系／生涯總成績」模式。

**設計多**：媒體與新聞集錦（news/thread/tweet/video ＋縮圖，**無資料來源**）、sparkline 走勢（需 0-100 的 form 序列，**無此資料**）、人物 `summary`。

### 2.4 名詞（架構性衝突，非樣式問題）

- **設計**：單頁 `/magazine/glossary`，搜尋框 + 分類分區 + 卡片，**點卡片開 modal**。
- **我們**：`/glossary` 索引 + 每則獨立 `/glossary/[slug]` 靜態頁（`dynamicParams = false`、24 則 MDX）。

> ⚠️ **全面 modal 化會直接砸掉 SEO**。`requirements.md` §8 成功樣貌寫明「球員頁與名詞頁能被 Google 搜到」，`app/glossary/[slug]/page.tsx` 也有 `generateStaticParams` ＋ OG metadata。

**建議**：保留獨立頁，**把設計 modal 的內容結構當成名詞頁的版面骨架**。設計的五段（簡述概念／對球員的意義／數據高低／站內相關／延伸參考）與我們 spec-04 的四層（判讀 → 定義算法小字 → 延伸 → 範例回連）大致對得上，只多出「簡述概念」條列。索引頁則採用設計的搜尋框＋卡片牆。

**分類也對不上**：

| 設計 | 我們 |
|---|---|
| 打擊數據 | `batting_adv` |
| 投球數據 | `pitching_adv` |
| **防守數據**（我們沒有） | — |
| 綜合評估數據 | 部分 `shared_adv` |
| 規則 | `roster` |
| — | **`standard`（標準數據）、`shared_adv`（打投共用）** |

**欄位對映**：`term ← name_zh`、`abbr ← name_en`、`desc ← blurb`、`points`/`meaning ← MDX body`、`scale ← bands`（見 §3 第一列，需改造）、`links ← sources`、`related ← 範例球員回連`。

### 2.5 「我想知道」（全新）

情境問題牆 + 主題標籤篩選 + modal 帶出對應名詞。純新功能，需要新內容模型（`FanQuestion`：question / context / tags / terms[]）。MDX 名詞庫可當素材，但問題本身要人工寫。**可與拉皮脫鉤，另行決定。**

## 4. 設計原則（摘自設計指南頁，供實作對齊）

1. 大字襯線標題建立雜誌般的視覺層級與個性。
2. 深藍為主、暖橘為輔，**強調色克制、只點在關鍵處**。
3. 數據與標籤一律等寬字體，維持對齊與工整。
4. 大量留白與雙欄節奏，讓輕度球迷也易於閱讀。

版面骨架：`mx-auto max-w-6xl px-6`（我們現行是 `max-w-5xl px-4` / 個人頁 `max-w-3xl`）；區塊標題 = kicker（`font-mono text-[11px] uppercase tracking-[0.3em] text-accent`）＋襯線大標；卡片 hover = `-translate-y-1` ＋ `shadow-lg` ＋暖橘邊框。

## 5. 待決四題（拍板後才開票）

### 5.1 球員照片 —— 與 PRD 正面衝突

`requirements.md:233` 已定：**只放球隊 logo，不放球員照片**（避開肖像權）。設計專案的封面跨頁、名冊卡、球員頁 hero **全以頭像為視覺主體**（`public/players/*.png`，alt 寫「示意插畫」）。

**選項**：(a) 以隊徽／剪影／插畫替代；(b) 重開這個產品決策。

> 設計本身已備妥不依賴照片的替代品：`magazine-player-detail.tsx:227` 的**姓氏浮水印**（`text-[12rem] text-primary-foreground/[0.06]`）正是為此而設計，把中央圓形頭像換成隊徽即可成立。

### 5.2 深色模式

設計只做亮色。→ 保留我們現有深色盤（需自配深藍系 dark token），或砍掉？

### 5.3 名詞頁 modal vs 獨立頁

建議保留獨立頁（SEO 是驗收條件），只借 modal 的版面骨架。

### 5.4 資料缺口

`summary`（人物介紹）、`headshot`、媒體連結、sparkline 走勢序列——四項設計有、DB 沒有。→ 補 schema，還是這幾區先不做？
