## 0. 一句話結論

搬的是 **design token 與版面樣板**，不是元件庫——設計專案通篇手刻 Tailwind，`@/components/ui/*` 的 import 數是 **0**。因此拉皮的成本不在依賴，在於**補齊設計沒畫到的那些頁面區塊**——出賽預告、首頁 empty state、archived、完整數據表、footer、行動版導覽，以及**把設計倚賴人物圖像的三個版面改成純字排＋隊徽**（§5.1）。

### 1.2 需要動的三件事

1. **字體（唯一的新東西，但走 `next/font/google`，免安裝）**
   現行 `app/layout.tsx:11` 只有 `Geist`。設計要三種角色分工，這是雜誌風格的骨幹：
   - `Noto_Serif_TC` → `font-serif`：所有標題、人名、區塊大標
   - `Noto_Sans_TC` → `font-sans`：內文
   - `Geist_Mono` → `font-mono`：**所有數據與標籤**（設計原則之一：數據一律等寬以維持對齊）

2. **`app/globals.css` 的語意 token**
   設計新增 8 個我們沒有的變數，並在 `@theme inline` 註冊：
   `--mlb / --aaa / --aa`（層級色）、`--up / --down`（升降・好壞）、各自的 `-foreground`。
   色盤本身：深藍 `--primary: oklch(0.32 0.09 262)`、暖橘 `--accent: oklch(0.68 0.17 45)`、頁面底 `oklch(0.98 0.006 250)`。

   - ⚠️ **設計沒有深色模式**：`:root { color-scheme: light }`、無 `.dark` 區塊（雖仍宣告 `@custom-variant dark`）。我們現行 `globals.css:85-117` 有完整深色盤。→ 待決 §5.2。

## 4. 設計原則（摘自設計指南頁，供實作對齊）

1. 大字襯線標題建立雜誌般的視覺層級與個性。
2. 深藍為主、暖橘為輔，**強調色克制、只點在關鍵處**。
3. 數據與標籤一律等寬字體，維持對齊與工整。
4. 大量留白與雙欄節奏，讓輕度球迷也易於閱讀。

版面骨架：`mx-auto max-w-6xl px-6`（我們現行是 `max-w-5xl px-4` / 個人頁 `max-w-3xl`）；區塊標題 = kicker（`font-mono text-[11px] uppercase tracking-[0.3em] text-accent`）＋襯線大標；卡片 hover = `-translate-y-1` ＋ `shadow-lg` ＋暖橘邊框。

## 5. 待決四題（拍板後才開票）

### 5.1 人物圖像 —— **已決議：一律不放，改純字排＋隊徽**（2026-08-12，batu）

#### 先更正一項事實

本文初稿把這題寫成「與 PRD 正面衝突」，**講重了**。`public/players/` 裡只有**兩個檔案**——`pitcher-portrait.png` 與 `batter-portrait.png`，六名球員按 `type` 共用，alt 寫「示意插畫」。**設計用的不是真人肖像，是角色示意圖**，並未違反 `requirements.md:233`（只放球隊 logo、不放球員照片）。

#### 真正的問題是密度，不是法務

我們目前 **5 名 tracked 球員**。照設計原樣，名冊頁會是五張卡、四張投手圖一模一樣。頭像框在設計稿裡好看，是因為那是「一整版不同人臉」的視覺假設；換成兩張圖輪播，80×80 的框就從資產變成噪音——**比留白更糟**。

**⇒ 決議：不放任何人物圖像（連示意插畫也不放）。** 圖像位置改由字體排印與隊徽承擔——雜誌風格本來就吃這套，設計指南的四條原則第一條（大字襯線建立視覺層級）正是這個意思。

#### 三個缺口各自怎麼補

| 位置 | 設計原本 | 改為 |
|---|---|---|
| **球員頁 hero** | 128/160 圓形頭像 + `ring-4 ring-accent`（`magazine-player-detail.tsx:234`） | **隊徽**。深藍底＋暖橘圈＋隊徽，姓氏浮水印（`:227`，`text-[12rem] text-primary-foreground/[0.06]`）本來就在，版面撐得住 |
| **名冊卡** | 80×80 方框頭像（`roster-page.tsx:32`） | **拿掉圖框、純字排**。設計自帶元素夠用：編號浮水印（`:27`）＋暖橘短線（`:44`）＋襯線大名＋mono 英文名；隊徽縮成 20px 掛在隊名旁 |
| **首頁封面跨頁** | `min-h-[380px]` 半版大圖（`magazine-page.tsx:42`） | **引言跨頁**（quote spread）。左半放大字襯線的**近況一句話**＋層級 badge，右半維持四格數據。雜誌本來就有這個形式，不需要圖 |

#### 隊徽的來源

`teams.mlbTeamId` 是 PK（`lib/db/schema/identity.ts:20`），對得上 MLB 靜態 logo；但目前 `public/` 只有 `og-default.png`，schema 亦無 logo 欄位。

- **把 30 支大聯盟隊徽下載進 `public/`，不 hotlink 第三方 CDN。**
- **小聯盟一律用母隊隊徽**——與 2026-08-07「中文隊名」那題同構（小聯盟不逐支處理、由 `parentOrgTeamId` 推導），201 支 affiliate 都有母隊參照，未來新增的隊自動涵蓋。
- 落地方式：`public/logos/` ＋ 一個走母隊推導的 `teamLogo(teamId)` helper。

> **⏳ 仍未定：隊徽這張票的時機。** 可以是拉皮的前置票，也可以先出「留白版本」（hero 只有姓氏浮水印、名冊卡純字排、隊名不掛徽）之後再補。三個版面在沒有隊徽時都成立，故不阻斷主線。

### 5.2 深色模式 —— **已決議：不做**（2026-08-12，batu）

設計只做亮色（`:root { color-scheme: light }`、無 `.dark` 區塊）。決議跟進，不自配深藍系 dark token。

**這不是移除功能，是刪未曾生效的程式碼**——實測全 repo：

- 沒有任何地方掛 `.dark` class（無 theme toggle、無 `next-themes`、`<html>` 上也沒有）。
- `globals.css:5` 的 `@custom-variant dark (&:is(.dark *))` 是 **class-based**，不吃 `prefers-color-scheme`。

⇒ `globals.css:85-117` 那 33 行深色盤**從未被觸發過**。

**連帶清理**（兩處僅有的 `dark:` 用法，同樣不可達）：

- `components/ui/button.tsx`：shadcn 原樣帶來的 `dark:` variant，無害，可留可清。
- `components/player-detail/upcoming.tsx:68`：`dark:text-emerald-400`——勝敗色改吃 `--up`／`--down` token 後這條自然消失。

### 5.3 名詞頁 modal vs 獨立頁

**決議方向：先 A、把 B 當後續 polish。**（2026-08-12 討論）

問題不是「modal 不好」，而是**「只有 modal」會拿掉 24 個可被索引的 URL**。設計那頁的 modal 是純 client state：卡片是 `<button>`（`glossary-page.tsx:204`），詳解在 `if (!rendered) return null`（`:273`）之後才存在。

#### 會掉什麼

| 現在有 | modal-only 之後 |
|---|---|
| 24 個 `/glossary/[slug]` 靜態頁 | 1 個 `/glossary` |
| 每則獨立 title／description／OG／Twitter（`app/glossary/[slug]/page.tsx:24-39`） | 只剩索引頁一張通用卡 |
| sitemap 24 條（`lib/seo/sitemap.ts:12-14`） | 0 條 |
| 站內有真連結指向每則名詞 | 卡片是 `<button>`，爬蟲走不進去 |

長尾查詢是名詞庫的主要獲客路徑——「wRC+ 是什麼」「FIP 中文」本來一頁精準對一題，全塞進一頁後 24 個主題互相稀釋。

> **排除一個看似可行的補救**：把 24 份詳解都 SSR 進 DOM 再用 CSS 藏起來——**不管用**。索引單位是 URL 不是 DOM 片段，隱藏內容還會被降權。

#### 比 SEO 更硬的一條

名詞頁不只是 SEO 資產，它是兩個機制的掛載點：

1. **雙向連結**（spec-04 §D）：`components/player-detail/season-stats.tsx:150` 的進階數據每項都連 `/glossary/${metricSlug(key)}`。名詞頁沒了，這些連結沒有去處。
2. **build-fail 護欄**：`getRegistry()` 在 `app/glossary/[slug]/page.tsx:51` 被呼叫，build 時只要有顯示中的 metric 缺名詞頁就炸。這道「名詞頁先行」的保險是掛在名詞頁的 render 上的。

而 `requirements.md` §8「球員頁與名詞頁能被 Google 搜到」是**驗收條件**，不是偏好。

#### 但設計師的判斷不是錯的

在索引頁掃過 24 張卡、想確認某則、看完回到原位——這個情境用整頁跳轉確實比較差。modal 解的是真問題，只是不能是唯一入口。

#### 三個選項

| | 做法 | 評價 |
|---|---|---|
| **A**（先做） | 索引頁採用設計的搜尋框＋卡片牆，卡片是真 `<Link>`，點擊進 `/glossary/[slug]` 全頁；**全頁版面用 modal 那五段骨架**（簡述概念／對球員的意義／數據高低／站內相關／延伸參考） | SEO 零風險、最快看到成果；失去「不離開索引頁」的閱讀感 |
| **B**（後續 polish） | **Intercepting routes**：卡片一樣是真 `<Link>`，加 `app/@modal/(.)glossary/[slug]/page.tsx` 攔截 client-side 導航顯示 modal；直接輸網址／重新整理／爬蟲則走原本全頁。同一份 MDX body 兩邊共用，URL 也會變（可分享、可回上一頁關閉） | 兩全。代價：root layout 要加 `@modal` slot；設計的雙 rAF 進場動畫要改寫（route 切換本身已延遲一拍）。**⚠️ 未實測** intercepting route 配我們 `await import(...content/glossary/${slug}.mdx)` 的動態 MDX 匯入在 Next 16 的行為 → 開票前需一次小 spike |
| **C** | 索引頁 modal 只放「預覽＋看完整說明」按鈕，深度內容仍在全頁 | 兩邊都不夠好，不建議 |

**順序理由**：拉皮的價值主要在視覺，modal 是錦上添花。先把 24 頁的版面換成設計骨架、索引頁補上搜尋與分類卡片牆，是風險最低的一刀；視覺落地後再花一張票做 B，spike 失敗也只是退回 A，不擋主線。

### 5.5 sparkline 走勢 —— ⏳ 待決

**它是什麼**：`components/sparkline.tsx`（57 行純 SVG，無座標軸、無刻度、線尾一點），用在球員頁「近期比賽紀錄」下方，每層級一張卡，標題「近七場狀態走勢」（`magazine-player-detail.tsx:298-321`）。

**兩個坑**：

1. **餵它的數字不存在**。`form: number[]`（如林昱珉 `[58, 62, 55, 70, 66, 74, 80]`）是 0-100 的「狀態分數」——**不是任何棒球數據**，StatsAPI 沒有、我們 DB 也推不出來，是設計為了填圖自行編造。要上真值得先定義這個分數怎麼算，**那才是工作量，畫圖不是**。
2. **自我正規化**（`range = max - min || 1`，取自資料本身）⇒ **只表達形狀、不表達幅度**。從 58 爬到 80 的球員，跟打擊率在 .290–.295 抖動的球員，畫出來一模一樣。當裝飾可以，當數據讀會誤導。

**三條路**：

| | 做法 | 評價 |
|---|---|---|
| **A** | 整區不做 | 最省；球員頁少一塊，版面靠「近期比賽紀錄」撐得住 |
| **B**（建議） | 改畫**季內累積走勢**（打者 season-to-date OPS、投手 season-to-date ERA 隨比賽日推移） | 資料現成（`game_*_lines` 已有逐場）、平滑好讀、語意誠實。必須在圖上標明指標名與起訖值，**不可無標示** |
| **C** | 保留「狀態分數」概念但定義它 | 等於開一個小 spec（權重／樣本／層級校正），為一張裝飾圖不划算——且那個分數會成為全站唯一沒有出處的數字 |

> **不比照媒體用 mock**：媒體是「等資料源」，補上來源就換掉；sparkline 是「等定義」，mock 一個編造的分數等於把待決問題畫進 UI 裡。性質不同。
