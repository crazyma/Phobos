狀態模型：歸屬 × 健康（兩軸）

PRD 原文「active / IL / minors」混了兩個維度，拆為：

  • 歸屬軸：在哪一級哪一隊——MLB／3A／2A／…／DFA 中／FA／已釋出／已離開美職體系。
  • 健康軸：active／IL（各層級都可能進 IL，小聯盟 IL 也要能表達）。

呈現時組合成一句（例：「3A・傷兵名單」「大聯盟・出賽中」「DFA 等待處置」）。

投影規則：目前狀態一律由 TransactionEvent 事件流推導，時間軸與目前狀態天然一致、不可能矛盾。上游漏事件時，以人工補錄事件修正，禁止直接改狀態快照。

成績模型

  • SeasonStats 最細粒度＝球季 × 層級 × 球隊；同季同層級跨隊（交易）分列，另出層級合計。不做跨層級加總（不同層級數據不可比）。
  • GameLine 帶角色軸：打者欄位組／投手欄位組各一型；同球員同場可兩列。
  • 資料自 2020 球季起；「生涯新高」pattern 照樣稱生涯，接受基準誤差（多數現役球員 2020 後登美職）。
  • 進階數據 best-effort：低階算不出（缺聯盟/球場係數）就不顯示。

首頁「24 小時」窗口

錨定「最新一個已結算的美國比賽日」全部賽果＋其後發生的動態事件，不是滾動 24 小時時鐘窗口——避免同一比賽日的內容在台灣時間下午陸續「過期消失」，語意也跟一天兩批的同步節奏相容。

近況一句話（RecentForm）生成規則

  1. Pattern 優先序：生涯／球季新高 → 連續紀錄 → 單場亮點 → 近 N 場數據。多 pattern 同時成立取最高優先。
  2. 狀態 fallback：無近期賽事資料時退化為狀態句——「傷兵名單中，最後出賽 6/12」「休賽期」「新人聯盟（無逐場資料）」。此欄永不為空。
  3. 每批同步重算（回填修正自動反映）。

名詞庫（GlossaryTerm）模型

  • 級距 × 層級：級距對照做 MLB／3A／2A 三組；1A 以下不給級距，數據旁附「低階層級數據僅供參考」警語。低階聯盟無權威參考區間，不硬做。
  • 指標 ↔ 名詞頁對應：球員頁僅能顯示已有對應名詞頁的指標——換進階指標時名詞頁先行，舊名詞頁保留不下架。此規則保證雙向連結永不斷鏈。
  • 範例球員回連：自動挑選（追蹤中＋該指標有值＋樣本足夠，依層級優先）；挑不到則整塊隱藏，不硬塞。

出賽預告語意

  • 「確定先發」僅適用投手（probable pitcher，賽前數日可知）。
  • 野手／中繼／後援一律「可能出賽」＝球隊有比賽且球員健康在名單——不承諾打線（打線賽前 3~4 小時才公布，一天兩批同步必然錯過；不為此加開第三批）。

季累計每批整季重拉（追蹤球員僅十餘人，成本可行）
